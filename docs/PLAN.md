# Plan — github: GitHub Actions as the CI of a deployment

Part of the "Despliegue guiado" wave (`https://github.com/webtyp/docs/blob/main/DEPLOY_WIZARD_MASTER_PLAN.md`,
decisions D8, D11, D19, D29, D39). This new module implements the `deploy.CI` interface of
`webtyp.com/deploy` for GitHub Actions. It is what lets `webtyp/app` check that GitHub is ready,
write the deploy workflow, deliver CI secrets and start a deploy, without anyone running
`gh secret set` by hand.

**Prerequisite:** `go get webtyp.com/deploy@latest` must provide `deploy.CI`, `deploy.Job`,
`deploy.Destination`, `deploy.Missing`, `deploy.Run`, `deploy.RunState`. If it does not, **stop**
and say so in the PR: the deploy plan of this wave publishes them.

## Tools

```bash
go install webtyp.com/devflow/cmd/gotest@latest

```

## Design gate

1. **Prior art.** `gh` itself (`gh secret set`, `gh workflow run`, `gh run view`), Fly's
   `fly deploy` from a GitHub Action, Vercel's Git integration. All start a deploy from a push or
   an explicit dispatch and report the run. Here the developer's own `gh` session is the
   credential (no separate PAT).
2. **Names.** `github.Actions` (the CI id a project writes in `config/deploy.go`), `github.CI`
   (the implementation), `github.New`, `github.Config`, `github.Runner`, `github.ExecRunner`.
3. **Ledger.** Manual steps removed per project: every `gh secret set` and the hand-written
   workflow. New concepts for the developer: 0 (they only write `github.Actions`).
4. **Where.** A new repo: GitHub knowledge must not live in `deploy` (contracts only), `ghaction`
   (YAML only, no domain) or `devflow` (a CLI bundle `app` should not import).
5. **Deletes.** `github.go` placeholder from the repo template.

## Stage 1 — identity and construction

`github.go` (replace the template content):

```go
package github

import "webtyp.com/deploy"

// Actions is the CI id a project declares in config/deploy.go.
const Actions deploy.CIID = "webtyp.com/github.Actions"

// Runner runs an external command in dir, writing stdin to it, and returns
// its stdout. Secret values travel only through stdin.
type Runner interface {
	Run(dir, stdin, name string, args ...string) ([]byte, error)
}

// ExecRunner runs commands with os/exec.
type ExecRunner struct{}

// Config configures a CI. Both fields are required.
type Config struct {
	RootDir string // the project root (contains .git and go.mod)
	Runner  Runner
}

// CI implements deploy.CI for GitHub Actions.
type CI struct{ /* unexported fields */ }

// New returns a CI, or an error if a Config field is missing.
func New(cfg Config) (*CI, error)

var _ deploy.CI = (*CI)(nil)
```

`ExecRunner.Run` uses `exec.Command`, sets `Dir`, pipes `stdin`, returns stdout; on failure the
error includes stderr (never stdin). `ID()` returns `Actions`.

## Stage 2 — `Check(p, job)`

Every external call goes through `Runner`. Results in this order, each a `deploy.Missing` with
`lang.Text` constants (Stage 6):

| # | Probe | Missing when | Fix |
|---|---|---|---|
| G1 | `gh --version` | command fails | `FixManual`: install GitHub CLI (`https://cli.github.com`) |
| G2 | `gh auth status` | non-zero exit | `FixManual`: run `gh auth login` in a terminal and follow the device code |
| G3 | `gh repo view --json nameWithOwner -q .nameWithOwner` (in `RootDir`) | fails or empty | `FixManual`: this folder has no GitHub remote; create it (`gh repo create`) |
| G4 | read `RootDir/.github/workflows/deploy.yml` | absent or differs from `render(p, job)` | `FixAutomatic` |
| G5 | `git show origin/main:.github/workflows/deploy.yml` | differs from `render(p, job)` | `FixManual`: commit and push `.github/workflows/deploy.yml` |
| G6 | for each name in `job.Secrets`: present in `Secrets(p).Has` | — | none here: the Target that owns those secrets reports them (`deploy.Target.Check`) |

If G1 or G2 is missing, stop and return only those (the rest cannot be probed).

## Stage 3 — the workflow

Unexported `render(p deploy.Plan, job deploy.Job) []byte` with `webtyp.com/ghaction`
(`ghaction.Workflow{...}.Render()`):

- Header: `# GENERATED by webtyp from config/deploy.go — do not edit. Change config/deploy.go and run Provision from the webtyp DEPLOY tab.`
- `name: Deploy`; `on: push: branches: [main]` and `workflow_dispatch`.
- `permissions: contents: read`.
- One job `deploy`, `runs-on: ghaction.DefaultRunsOn`; job-level `env`: one entry per
  `job.Secrets` name, value `${{ secrets.<NAME> }}`.
- Steps: `ghaction.CheckoutStep()`, then one step `uses: job.Uses` with `job.With` in order.

`Provision(p, job)` writes it to `RootDir/.github/workflows/deploy.yml` (creating directories) only
when content differs. It never commits or pushes.

## Stage 4 — secrets

`Secrets(p) deploy.Destination` returns a value whose:

- `Has(key)`: `gh secret list --repo <repo> --json name` → parse JSON (`encoding/json`) → is
  `key` there.
- `Put(key, value)`: `gh secret set <key> --repo <repo>` with `value` on **stdin**. The value never
  appears in `args`, in an error or in a log.

`<repo>` is the result of probe G3, resolved once per `CI` and cached in an unexported field.

## Stage 5 — release and status

- `Release(p)`: `gh workflow run deploy.yml --repo <repo> --ref main`; then
  `gh run list --workflow deploy.yml --repo <repo> --event workflow_dispatch --limit 1 --json databaseId,url,createdAt`
  until a run created after the dispatch time appears (poll every 2 s, at most 30 s; the clock and
  sleep are unexported seams so tests do not wait). Returns `deploy.Run{ID, URL}`; timeout →
  `ErrRunNotFound`.
- `Status(r)`: `gh run view <ID> --repo <repo> --json status,conclusion` →
  `queued|waiting|pending` → `RunQueued`; `in_progress` → `RunInProgress`;
  `completed`+`success` → `RunSucceeded`; `completed`+anything else → `RunFailed`.

## Stage 6 — errors and texts

`errors.go`: `ErrNoRootDir`, `ErrNoRunner`, `ErrNoRemote`, `ErrRunNotFound`, `ErrUnknownRunStatus`
(English, `errors.New`).

`texts.go`: one `lang.Text` constant per Missing item and step of Stage 2 (English), e.g.
`textGhMissing lang.Text = "GitHub CLI"`, `textGhMissingWhy = "webtyp uses it to reach GitHub with your own session"`,
`textGhInstall = "Install it from https://cli.github.com and open the project again"`.

`lang.json` (8 columns `es zh hi ar pt fr de ru`; `es` mandatory) and `dictionary.go` with
`func Dictionary() []byte`, exactly like `https://github.com/webtyp/devtui/blob/main/dictionary.go`.
Run `langc sync`.

## Stage 7 — tests (`tests/`, external package)

A fake `Runner` that records `(dir, stdin, name, args)` and returns canned outputs per command.

| Branch | Test |
|---|---|
| G1–G5 | one test per row of Stage 2; G1/G2 missing → only that item returned |
| W1 | `render` output for a misitio-like plan contains the header, `workflow_dispatch`, job env from `job.Secrets`, and the `uses`/`with` of the job (compare against `tests/testdata/deploy.yml`) |
| W2 | `Provision` does not rewrite an identical file (mtime unchanged) |
| S1 | `Put("K","v")` sends `v` on stdin and no recorded arg contains `v` |
| S2 | `Has` parses the JSON list |
| R1 | `Release` returns the run created after dispatch; older runs are ignored |
| R2 | no new run within the window → `ErrRunNotFound` |
| R3 | `Status` maps every row of Stage 5 |
| C1 | `New` with empty `RootDir` or nil `Runner` → error |
| L1 | with `lang.OutLang("es")` a Missing item's text translates |
